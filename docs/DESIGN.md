# 设计说明与实现状态

本文档记录 NetGuard 的设计决策、模块接口与实现进度，供后续开发参考。

## 1. 术语

| 术语 | 含义 |
| --- | --- |
| 受控程序 | 配置中被列入 `apps` 的可执行文件 |
| 封禁窗口 | `TimeWindow`，一个半开时间区间 `[start, end)` 与适用星期的组合 |
| 生效 | 当前时刻存在至少一个受控程序处于封禁窗口内，且总开关开启，且无有效临时放行 |
| 边界 | 生效状态发生变化的时刻，精确到分钟 |
| 临时放行 | 经过认证后在限定时间内解除拦截，到期自动恢复 |
| 水位线 | 记录在案的最近可信系统时间，用于检测时钟回拨 |

## 2. 分层

```
core（与平台无关）          win（Windows 实现）
  config   配置模型            wfp     过滤器协调
  schedule 排程计算            svc     服务生命周期
  totp     动态口令            etw     进程事件订阅
  auth     认证与锁定          timer   高精度等待定时器
  mac      完整性签名          http    WebUI 与接口
  guard    哈希与保护名单      main    入口与子命令
```

`core` 不依赖任何 Windows API，可在任意平台编译与测试，因此单元测试在 Ubuntu 上执行，Windows 作业只负责构建。

## 3. 数据模型

```rust
pub struct Config {
    pub version: u32,          // 当前为 1
    pub enabled: bool,         // 总开关
    pub apps: Vec<AppRule>,
    pub hashes: Vec<String>,   // 已知恶意/规避副本的 SHA-256
    pub auth: AuthConfig,
}

pub struct AppRule {
    pub name: String,
    pub path: String,          // 必须为绝对路径且以 .exe 结尾
    pub schedule: Schedule,
}

pub struct Schedule { pub windows: Vec<TimeWindow> }

pub struct TimeWindow {
    pub days: u8,    // bit0=周一 … bit6=周日
    pub start: u16,  // 当天分钟数 0..1440
    pub end: u16,    // 半开区间；end < start 表示跨午夜
}
```

约束：

- `windows` 为空表示全天封锁；需要「不封锁」应删除该规则而非写零长度窗口。
- `start == end` 被拒绝，避免歧义。
- `days == 0` 或高位被置位被拒绝。
- `path` 必须是 `.exe`，且不得属于系统关键进程保护名单。

## 4. 生效判定

`schedule::evaluate(cfg, now, override_until) -> Evaluation`

1. `enabled == false` 时直接返回未生效。
2. 对每个受控程序判断其排程是否命中当前时刻（同天窗口直接比较；跨午夜窗口需回看前一天）。
3. 命中集合非空时，若 `override_until > now`，则结果为「未生效但处于临时放行」，同时仍报告被命中的程序名，以便界面提示。
4. `next_change` 从下一分钟起逐分钟向后扫描，最多 8 天，返回生效集合首次与当前不同的时刻；临时放行到期时刻亦作为候选。

由 `next_change` 驱动单条等待定时器，不使用轮询。

## 5. 认证

四种因子组合：无、密码、动态口令、双因子。

- 密码：Argon2id，默认参数 m=19 MiB、t=2、p=1，随机 16 字节盐，存储为 PHC 字符串。
- 动态口令：RFC 6238，SHA-1、6 位、30 秒步长，允许前后各 1 步容差；校验采用恒定时间比较；通过后记录计数器，同一计数器重复使用被拒绝（防重放）。
- 恢复码：10 个，Base32 编码的 8 随机字节（显示为 `XXXXX-XXXXX`），仅存 Argon2id 散列，使用后从列表移除。
- 锁定：连续 5 次失败锁定 900 秒，计数与锁定截止时间持久化；成功登录清零。
- 会话：`HttpOnly` + `SameSite=Strict` Cookie，15 分钟无操作过期；敏感操作需 5 分钟内重新认证，并附带服务端签发的一次性挑战。

`AuthConfig::check_login` 具有副作用（更新失败计数、记录 TOTP 计数器），调用方必须在返回后立即持久化配置。

## 6. 完整性

- `mac::sign(key, cfg)` 对 `serde_json::to_vec(&cfg)` 求 HMAC-SHA256，输出小写十六进制写入 `config.mac`。
- 校验使用恒定时间比较；失败时服务进入封锁状态并拒绝加载配置。
- 密钥由安装时随机生成并经 DPAPI 保护存放。

## 7. 进程哈希守护

- 订阅 `Microsoft-Windows-Kernel-Process` 的进程启动与退出事件。
- 仅当进程文件名命中受控程序名单时才处理，其余事件零开销。
- 命中时挂起进程、流式计算 SHA-256（上限 512 MiB）、与 `hashes` 比较，命中则对该新路径追加临时过滤器，随后恢复进程；进程退出时回收临时过滤器。
- 目标挂起时长小于 5 毫秒。

## 8. 时钟回拨防护

- 每次状态计算后持久化「最近可信时间」。
- 以单调计时器与系统时间之差交叉校验；若系统时间倒退超过 120 秒，判定为时钟调整，冻结在封锁状态，界面显示告警并记录日志。

## 9. 接口

默认仅监听 `127.0.0.1:47811`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/login` | 按已启用因子校验，返回会话 Cookie |
| POST | `/api/logout` | 结束会话 |
| GET | `/api/state` | 当前生效状态、被拦程序、下一边界、剩余时间 |
| GET | `/api/config` | 读取配置（凭据字段脱敏） |
| PUT | `/api/config` | 更新配置（需重新认证与挑战值） |
| POST | `/api/override` | 临时放行指定分钟数 |
| POST | `/api/setup` | 首次初始化：选择因子、设置凭据、生成 TOTP 密钥与恢复码 |
| GET | `/api/log?since=` | 读取事件日志 |

WebUI 为原生 HTML/CSS/JavaScript，无前端构建步骤，编译时以 `include_bytes!` 内嵌。

## 11. 验收标准

1. 名单内程序无法建立出站连接，名单外程序不受影响。
2. 开启移动热点后，接入设备可正常上网，且名单内程序仍无法连接。
3. 封禁窗口边界翻转误差不超过 30 秒。
4. 睡眠唤醒、系统时间调整、网络接口变化后状态在 5 秒内恢复正确。
5. 系统时间向前调整 2 小时不会解除封锁。
6. 服务被强制结束后，拦截仍然生效；重启服务后自动恢复协调状态。
7. 复制并改名受控程序后，新文件仍被拦截。
8. 连续 5 次认证失败后锁定 15 分钟。
9. TOTP 同一口令第二次提交被拒绝。
10. 配置文件改动 1 字节即进入封锁状态。

## 12. 已知限制

- 管理员取得所有权后可删除过滤器或停止相关服务。
- 安全模式不加载基础过滤引擎。
- 按程序拦截无法阻止改用其他浏览器或经代理转发。
- 无内核驱动，不覆盖驱动层与原始套接字。
