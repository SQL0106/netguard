# NetGuard

Windows 应用级网络访问控制程序。用于在指定时间段内禁止指定应用程序访问网络，而不影响本机热点共享、不影响其他应用程序的正常联网。

本项目为个人使用与学习目的而编写，采用 MIT 许可证。

---

## 一、设计目标

1. **指定应用断网**：按可执行文件路径精确拦截出站连接，仅拦截名单内的程序。
2. **指定时间生效**：支持按星期与时段配置封禁窗口，支持跨午夜窗口，边界精确到分钟。
3. **不影响热点**：拦截建立在应用层（ALE）出站检查上，局域网转发流量不经过该层，因此开启移动热点时，连接的设备仍可正常上网。
4. **不易被随意解除**：过滤器为持久化内核对象，服务停止后仍然生效；进程哈希守护可阻止改名/复制副本规避；配置带完整性校验，篡改后进入封锁状态。
5. **不做低效轮询**：时间边界由单次阻塞等待驱动（到点或被唤醒才重算），进程监控采用 ETW 事件订阅，配置外部改动由目录变更通知触发，空闲时无周期性扫描。
6. **双形态交互**：本机 Web 管理界面（WebUI）与命令行客户端（ngcli），二者共用同一套 HTTP 接口。

## 二、体系结构

| 组件 | 职责 |
| --- | --- |
| `netguard.exe` | 以 LocalSystem 身份运行的服务。负责网络过滤、排程计算、认证、WebUI 与配置管理。 |
| `ngcli.exe` | 命令行客户端，调用服务提供的 HTTP 接口，不直接操作配置。 |
| WebUI | 由服务内嵌提供，默认监听 `127.0.0.1:47811`，仅本机可访问。 |

关键实现要点：

- **Windows 过滤平台（WFP）**：为每个受控程序在 `FWPM_LAYER_ALE_AUTH_CONNECT_V4/V6` 层创建阻断过滤器，条件为 `FWPM_CONDITION_ALE_APP_ID`。全部过滤器标记为 `FWPM_FILTER_FLAG_PERSISTENT`，服务异常退出后拦截依旧有效。
- **状态协调（reconcile）**：服务启动时枚举自身 Provider 下的全部过滤器，与配置求差集，只增删必要的条目，不重建全量。
- **进程哈希守护**：订阅 `Microsoft-Windows-Kernel-Process` 事件，仅在进程名命中名单时读取文件并计算 SHA-256，命中黑名单哈希则对新路径追加临时过滤器，进程退出后回收。
- **时间驱动**：任意时刻只保持一条高精度等待定时器指向下一个状态边界；配置变更、电源唤醒、系统时间调整、网络接口变化时重新计算。
- **时钟回拨防护**：持久化最近可信时间水位线，并结合单调计时器交叉校验；检测到显著回拨时冻结在封锁状态并记录告警。

## 三、认证方式

安装时选择单因子或双因子：

| 模式 | 凭据 |
| --- | --- |
| 无 | 不做认证（仅建议在隔离环境使用） |
| 单因子（密码） | Argon2id 密码散列 |
| 单因子（动态口令） | TOTP（RFC 6238，SHA-1 / 6 位 / 30 秒） |
| 双因子 | 密码 + TOTP |

- TOTP 密钥在 WebUI 中生成，并以二维码与 Base32 文本两种形式显示，可直接由常见身份验证器扫描导入。
- 密钥与密码散列在落盘前经 DPAPI（机器范围）加密。
- 连续 5 次校验失败锁定 15 分钟，失败计数持久化。
- 提供 10 个一次性恢复码，使用后即失效。
- 修改配置、临时放行、卸载等敏感操作需重新认证（有效期 5 分钟）。
- 会话 Cookie 为 `HttpOnly` 且 `SameSite=Strict`，15 分钟无操作过期；敏感请求需附带服务端签发的一次性挑战值。

## 四、构建

本项目**只在 GitHub Actions 中编译**，不在开发机上执行 `cargo build`。

工作流 `.github/workflows/ci.yml` 包含三个作业：

- `core`：在 Ubuntu 上执行格式检查、静态检查与单元测试；日志始终上传（`if: always()`）。
- `windows`：在 Windows 上执行 release 构建；可执行文件与构建日志始终上传。
- `release`：推送 `v*` 标签时创建 Release 并附带构建产物。

依赖缓存由 `Swatinem/rust-cache` 提供，以工作区与作业为键。

手工触发构建：进入 Actions 页面选择 `CI` → `Run workflow`。

## 五、安装

1. 从 Releases 下载 `netguard.exe` 与 `ngcli.exe`。
2. 以管理员身份执行 `install.ps1`，脚本将完成：复制程序、注册服务、创建 `C:\ProgramData\NetGuard` 并设置访问控制、启动服务。
3. 打开 `http://127.0.0.1:47811` 完成初始化：设置认证方式与凭据、生成 TOTP 密钥、保存恢复码、添加受控程序与时段。

卸载：`install.ps1 -Uninstall`（保留数据目录）或 `install.ps1 -Uninstall -Purge`（一并删除 `C:\ProgramData\NetGuard`）。

安装脚本在注册服务后会收紧服务控制权限：SYSTEM 持有启停与配置权限，Administrators 仅保留查询权限。因此普通管理员账户无法使用 `sc stop` 或 `sc delete` 停止、删除服务；需要卸载时应以 SYSTEM 身份或取得服务所有权后执行。此限制与「配置目录仅 SYSTEM 可写」共同构成抗绕过基线。

服务被配置为失败后自动重启（三次，间隔五秒），并在系统时间变更、网络接口变化与电源状态变化时重新计算拦截状态。

### 无人值守安装

适用于批量部署或系统镜像制作。安装脚本支持命令行参数与预置配置文件，全程无需人工确认：

```powershell
.\install.ps1 -Silent `
              -Config .\preseed.json `
              -PasswordFile .\pw.txt `
              -RecoveryOut .\recovery-codes.txt
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `-Silent` | 不产生任何交互提示，日志写入 `C:\ProgramData\NetGuard\install.log` |
| `-InstallDir` | 安装目录，默认 `C:\Program Files\NetGuard` |
| `-Config` | 预置配置文件，格式见下文 |
| `-Factors` | 认证因子组合：`none`、`password`、`totp`、`both`，覆盖配置文件中的取值 |
| `-Password` | 初始密码；不建议使用，因其会出现在命令历史与进程列表中 |
| `-PasswordFile` | 从文件首行读取初始密码，文件仅需安装账户可读 |
| `-PasswordStdin` | 从标准输入读取初始密码，适合由其他程序调用 |
| `-TotpSecret` | 预先指定的 Base32 动态口令密钥；省略时由程序生成 |
| `-RecoveryOut` | 将生成的恢复码以明文写入该文件，安装完成后应妥善保管并删除 |
| `-NoStart` | 完成注册但不启动服务 |
| `-Force` | 已有配置时覆盖，需同时提供凭据 |

退出码：`0` 成功，`2` 预置文件或参数解析失败，`3` 缺少必要凭据，`4` 配置校验失败，`5` 服务注册失败或权限不足。

`-Silent` 以外的场合，脚本会打印每一步的执行情况；所有错误同时写入数据目录下的日志文件。

预置配置文件与运行时配置结构一致，另可包含明文 `factors`、`password`、`totp_secret` 与 `recovery_code_count` 四个字段。安装时密码与恢复码会被散列化，明文不落盘，预置文件本身不被修改：

```json
{
  "version": 1,
  "enabled": true,
  "apps": [
    { "name": "示例程序", "path": "C:\\Program Files\\Example\\example.exe",
      "schedule": { "windows": [ { "days": 127, "start": 0, "end": 1440 } ] } }
  ],
  "hashes": [],
  "factors": "both",
  "password": "安装时被散列，之后不再以明文形式存在",
  "totp_secret": "",
  "recovery_code_count": 10
}
```

该流程等价于在 WebUI 中人工完成：选择因子、设置密码、生成动态口令密钥、导出恢复码。

## 六、配置

配置位于 `C:\ProgramData\NetGuard\config.json`，完整性签名位于 `config.mac`。

```json
{
  "version": 1,
  "enabled": true,
  "apps": [
    {
      "name": "示例程序",
      "path": "C:\\Program Files\\Example\\example.exe",
      "schedule": {
        "windows": [
          { "days": 31, "start": 1260, "end": 1320 }
        ]
      }
    }
  ],
  "hashes": [],
  "auth": { "factors": "both" }
}
```

字段说明：

- `days`：位掩码，第 0 位为周一，第 6 位为周日，`31` 表示周一至周五。
- `start` / `end`：当天分钟数，取值 `0..1440`，区间为半开区间 `[start, end)`。
- `end` 小于 `start` 表示跨午夜，例如 `1320 → 120` 表示 22:00 至次日 02:00。
- `windows` 为空表示全天封锁。
- `hashes`：SHA-256 十六进制字符串，用于识别改名或复制后的可执行文件。

配置文件权限仅授予 `SYSTEM` 完全控制、`Administrators` 只读。签名校验失败时服务进入封锁状态并记录日志，不加载被修改的配置。

系统关键进程（`svchost.exe`、`lsass.exe`、`csrss.exe`、`services.exe`、`wininit.exe` 等）一律拒绝加入名单，界面中相应条目置灰。

## 七、安全模型

采取的措施：

- 持久化 WFP 过滤器，服务停止或崩溃后拦截不失效。
- 服务注册为 LocalSystem，普通用户与管理员均无法通过服务控制命令停止（访问控制列表仅授予 SYSTEM 与控制台登录会话的有限权限）。
- 配置签名，篡改即封锁。
- 认证失败锁定、一次性挑战、TOTP 重放拒绝。
- 时钟回拨检测，避免通过修改系统时间提前解除封锁。
- 进程哈希守护，阻止复制改名规避。

明确的能力边界（请在使用前了解）：

- 拥有管理员权限并取得文件所有权的用户，可以直接删除 WFP 过滤器或停止安全中心相关服务，本程序无法阻止此类操作。
- Windows 安全模式不加载基础过滤引擎（BFE），此时拦截不生效。
- 若配置为按程序拦截，用户改用未被拦截的浏览器或经代理转发流量，即可绕过。
- 本程序不提供内核驱动，不拦截驱动层或原始套接字流量。

本程序的定位是**提高自我约束成本**，而非抵御拥有完全控制权对手的强制性安全边界。
